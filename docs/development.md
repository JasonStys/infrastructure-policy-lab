# Coding, documentation and dependency maintenance

Author: Jason Stys. Favor small readable modules, exact types, meaningful identifiers and documented safety boundaries; Big-O explains growth, measured benchmarks cover only their stated workload. Runtime is Python standard library only. Terraform models resource/configuration relationships; Rego independently expresses gate decisions; Bash drives portable validation.

Every authored Python module has a purpose header, typed functions and contract docstrings. Generated exact-line maps cover definitions, parameters and assigned variables. Terraform variables carry descriptions/validation, resource headers describe scope, and generated maps cover HCL blocks/attributes/references, Rego rule symbols/references and workflow/shell variables. Hash locks/fixtures/tool reports are generated data, not source logic. CI rejects stale maps and missing Python function/class docstrings. All tracked files are summarized in README; ignored state/tools/private evidence never enters that guide.

Format Python (`ruff format`), Terraform (`terraform fmt -recursive infra`) and Rego (`opa fmt -w policies`) before `python scripts/code_map.py`. Stage intended files, then run `python scripts/file_guide.py`, stage updated README and check both maps. Do not use giant modules, shell eval, SQL/string execution, dynamic imports or cloud credentials from inputs.

Dependency maintenance: review requirements-dev.in, regenerate complete portable hashes using isolated pip-tools 7.6.2 with `--generate-hashes --allow-unsafe --strip-extras`, audit all transitive versions and rerun every OS. Terraform 1.16.5 and AWS provider 6.68.0 are exact; .terraform.lock.hcl contains vendor signatures/checksums from init. Official Terraform/OPA/scanner URLs and SHA-256 digests are reviewed in tools.lock.json; hashes detect altered downloads but are not a substitute for trusted-source/lock review. Third-party binaries/provider code retain their own licenses; the repo's MIT terms cover authored code only.

Controls: add strict paths, known/private handling, negative/oracle tests and matching independent Rego expectations. Do not change expectations/silence failures to obtain green CI. Native mock output schema changes require actual tool evidence and adapter tests. Missing architecture/IAM/runtime evidence is a documented gap, not a passing claim.

Before publishing a provider update, run `terraform -chdir=infra providers lock -platform=linux_amd64 -platform=windows_amd64` against the origin registry, review the HashiCorp-signed package output and commit both platforms' unpacked hashes and vendor archive checksums. Initializing only Windows is insufficient for immutable Linux cached-package validation. CI retains `-lockfile=readonly`; do not remove checksum validation or silently mutate locks there. Other native architectures need separately reviewed platform hashes/tests; Python-only macOS CI does not validate a macOS AWS provider.

Release: structured author code review, staged/history secret checks, known advisory/high-critical dependency gates and workflow syntax; exact latest main must pass both workflows. Update measured docs, then recheck the documentation commit. This is source publication only, not production deployment; no installer/host/cloud daemon or paid account needed. Keep Actions artifact/cache uploads disabled unless separately reviewed with current storage.
