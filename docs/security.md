# Threat model, privacy and known assurance gaps

Assets: truthful selected-control evidence, private infrastructure names/settings/state/secrets, earlier reports and source/tool integrity. Untrusted: input JSON, nested IAM policy strings, unknown/sensitive masks, output paths and supplied workload prices. Trusted: reviewed source/tool locks, owned non-concurrent workspace, installed runtime and honest authenticated operator. No browser uploads or real AWS API calls occur in the runtime CLI.

Controls: bounded strict parsing, duplicate/type/nonfinite/depth rejection, final-file no-link checks, unknown/private field redaction, exact comparisons, unsupported/deletion/drift blocking, scoped TLS denial recognition and selected-key binding. Paths never drive a shell/cloud command. Reports are new-directory only; escape HTML and apply scriptless deny-default CSP. No raw values in findings, no ads/remote analytics. Source/test/tool dependencies are pinned with hashes; Actions least privilege/full action SHAs/no persisted checkout credentials; advisory and history secret scans plus security-extended CodeQL.

Limits: hostile operators can forge evidence, strip masks/delete checks, change locks or selected baseline. A semantic digest does not authenticate/anonymize a plan. Rego normalized inputs are trusted adapter output, not an authenticated API. Partial supported inventories can pass while whole-resource controls are absent. The example source is not a full architecture and does not manage default VPC resources, actual IAM authorization, all resource relationships, route connectivity, complete logs/retention, backup/restore or cloud billing. Small authored OPA checks are not a complete IaC misconfiguration/compliance scanner. Trivy is used for dependency vulnerabilities only; no full IaC security coverage is claimed or scan suppressions added.

Terraform mocks validate expressions, provider schemas and assertions, not real cloud APIs, effective IAM policies, KMS authorization, actual network filtering, region availability, backend concurrency or data durability. S3 versioning/encryption do not themselves grant least-privilege access. Account-root delegation in the example key policy is deliberate but requires independent IAM/key-policy review; wildcard Resource there means the enclosing KMS key, not generic least-privilege certification.

Unencrypted local plans/output and resource addresses can disclose secrets/private project names. Sensitive masks redact selected values only, not entire real plan contents or addresses; use private files and OS ACLs, never force-add real evidence. Windows mode 0700 is not an ACL guarantee. Path checks are defense-in-depth with trusted parents, not a race-proof sandbox. Meta CSP cannot block a hostile extension/altered file/web host; hosted reports require real authenticated access/TLS/HTTP headers. Author self-review is not independent penetration testing or security authorization. Nothing claims ATO/CIS/STIG certification.

No credential collection, existing workflow cleanup, billing/retention settings change, host hardening, Docker modification, resource deployment or data destruction is authorized/performed in this build. Future cloud use and cleanup require separate approval.
